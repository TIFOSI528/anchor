# Anchor 产品哲学

> 这份文档比技术架构更重要。所有 PR、所有功能取舍、所有设计 review 都应该回到这里对齐。

## 一句话总纲

**专注是一个连续光谱，不是开关。Anchor 是桅杆上的瞭望员，不是狱卒。**

## 三条立场

### 一、橡皮筋，而非牢笼

绝大多数专注力软件的失败，本质都是同一个错误：**把"对抗"当成产品机制**。

Cold Turkey 把你锁在屋里，Freedom 给你设定不可解除的封锁，One Sec 在你想点开 Twitter 时给你强制等待——它们都假设用户是需要被治理的对象，自己是治理者。

但真实的人不是这样运作的。**你不是不知道自己在摸鱼，你只是在那一刻没有足够的能量回去**。狱卒式产品的副作用是：

- 用户会找各种方式绕过（卸载、改时间、虚拟机），形成"猫鼠游戏"，最后产品被弃用。
- 用户对产品产生敌意，每次看到它都心情变差，恶性循环。
- 产品哲学要求"用户保持绝对自律"，但需要产品的人正是无法绝对自律的人——这是死循环。

Anchor 选择相反的姿态：**像一根隐形的橡皮筋，系在你和你的任务之间。你能挣脱，但你能感到它在拉你**。

具体到产品上：
- **永远保留逃生通道**——长按灵动岛 3 秒 = "我就是要摸鱼"，进入 5 分钟合法休息。
- **friction 是渐变的**，不是开关。30 秒只是提示，1 分钟才升级，3 分钟才到顶。给用户"反悔的黄金期"。
- **绿区里产品几乎隐形**——好工具应该让你忘了它存在。

### 二、渐进 friction：尊重人性

**所有的硬阻断都低估了一件事：意外切换的合理性。**

你在写代码，突然想到要回老板一条消息——这不是摸鱼，是工作。你打开 Twitter 是想搜一个技术问题，结果被信息流劫持——前半秒是工作，后半秒才变摸鱼。如果产品在第 0 秒就硬阻断，它会无差别误伤"工作切换"和"摸鱼切换"，被用户视为障碍。

Anchor 的 friction 设计有一条清晰的曲线：

```
0–30 秒：    灵动岛提示，屏幕无变化 ────── 给"反悔黄金期"
30s–1 分钟： 圆环倒计时，屏幕边缘光晕 ──── 提醒"你在漂"
1–3 分钟：   橙色拉回按钮，饱和度↓70% ──── 升级，但仍可拒绝
3 分钟以上： FrictionFog 加重，滚动锁定 ── 顶层 friction
```

红区（明确黑名单）是唯一例外——立即 50% 模糊。但**仍保留 5 秒缓冲**，避免误触惩罚。

这条曲线的设计原则：**任何瞬间的体验都应该"刚好比上一秒更不舒服一点点"**。突变会被反弹，渐变会被接受。

### 三、Local-first，开源对抗订阅制

> "你不应该为监控自己的注意力付订阅费。"

这句话借自 open-vibe-island 的精神，但在专注力赛道更加刺眼。专注力是关于**人的自律权和注意力主权**——这件事的产品本质上不该被订阅制锁住。

Anchor 的 Local-first 不是技术选择，是产品立场：

- **所有数据本地 SQLite，永远不离开你的电脑。** 没有账号，没有云同步（v1），没有遥测，没有"匿名分析"。
- **GPL-3.0 开源**——你可以 fork，可以改，可以审查每一行代码。
- **永久免费，没有 Pro 版**。如果未来要恰饭，会通过赞助 / 周边 / 企业自托管支持服务，而不是把核心功能锁起来。

这个立场带来的代价是：
- 跨设备同步（v2+）必须用 iCloud Drive / Tailscale 这类用户自己的基础设施，不能搭中心服务器。
- LLM 推断必须本地跑（Apple Foundation Models / 小模型），不能调云端 API（除非用户自己配 key）。
- 反作弊永远做不过闭源版（无法引入"防卸载"），但这是哲学选择——见第一条。

## 三条"不做"

Anchor 在 v1 周期内，**主动拒绝**以下方向。每一条都不是"还没来得及做"，而是"故意不做"：

### 不做 team mode / 社交压力

把"自律工具"加上"别人能看到你的状态"会立刻变成另一种产品——社交压力工具。这种产品有市场（Focusmate、虚拟自习室），但定位完全不同。**做了会污染主项目的语气**。如果将来要做，会以姊妹项目或单独 fork 的形式存在。

### 不做反作弊 / 不可卸载

短期看，反作弊能让产品对"自己骗自己"型用户更有效。但它和"橡皮筋"哲学根本冲突。如果一个产品需要把自己变成系统级监狱才能起作用，它就已经背叛了用户。Anchor 选择"用户技术上能轻易绕过，但情感上不愿意绕过"——这是更高难度的设计，也是更长期主义的选择。

### 不做跨平台（v1）

Linux/Windows 用户基数大，但灵动岛是 macOS 独有的产品形态。强行做跨平台会让"灵动岛"退化成"右上角浮窗"，产品的视觉语言被稀释 60%。**v1 macOS only，吃尽 Dynamic Island / Notch / Continuity / SwiftUI 的硬件和系统红利**，做到极致。其他平台等社区接力。

## 三条决策原则（写给未来的 PR review）

当任何功能讨论陷入"做不做、怎么做"的纠结时，回到这三条：

1. **绿区里它是否隐形？** 如果一个新功能让"专注中的用户"多看一眼 Anchor，应该被砍掉或下沉到设置。
2. **它有没有保留逃生通道？** 任何 friction 设计都必须有"我承认我就是要摸鱼"的出口。
3. **它能不能在飞机上离线工作？** 引入任何外部依赖前先问这个问题。
