# 商业化路线

> 决策记录，不是计划书。写下来是为了让"哪些能收费、哪些不能"有据可依——
> 免得半年后有人提一个 PR 把 Focus Lock 锁进 Pro 版，而没人记得为什么当初说不行。

## 结论

**核心功能永久免费，不做 Pro 版。** 收费只发生在四个地方：氛围包、支持者版、周边、企业支持。

这一条不是新决定，是 [`product-philosophy.md`](product-philosophy.md) 第三条早就写下的约束：

> **永久免费，没有 Pro 版**。如果未来要恰饭，会通过赞助 / 周边 / 企业自托管支持服务，而不是把核心功能锁起来。

## 为什么不做功能付费墙

三条理由，按硬度排序：

**一、GPL-3.0 让代码付费墙结构性无效。**
任何人都可以合法 fork 掉付费判断再分发。这不是道德问题而是工程问题：付费墙在 GPL 项目里挡不住任何有动机的人，却能百分之百地招来"某开源项目加付费墙"这类帖子。已发布的 0.1.x 永远是 GPL——即使未来换协议也追不回来。

**二、「免费 + 开源 + 无遥测 + 无订阅」本身就是最强的推广素材。**
主要竞品（Cold Turkey / Freedom / One Sec）全部收费。这是唯一能一句话讲清的差异点。要大力推广的时候把它拆掉，等于自废武功。

**三、先免费开源、火了再加付费墙，是哲学第一条警告的那种"猫鼠游戏"的起点。**
只不过对手从"用户想办法绕过软件"变成"用户觉得被骗"。后者更难修。

## 可以收费的四类

### 1. 氛围包（推荐主力）

漂移时屏幕怎么变，由 [`AmbienceProfile`](../Sources/AnchorCore/Drift/AmbienceProfile.swift) 描述，是**纯数据**。内置三套（褪色 / 压暗 / 起雾）永久免费且功能完整；额外的氛围可以作为付费包分发。

为什么这一类特别合适：

- **锁的是 taste，不是能力。** 免费用户不缺任何功能，付费用户买好看。这与"不该为监控自己的注意力付费"没有冲突——你付的是审美，不是自律权。
- **GPL 不传染资源文件。** 配方与配套素材以独立许可分发，不受 GPL 约束。这是唯一一个协议不会削弱的付费杠杆。
- **架构已经就绪。** 渲染器只认 `AmbienceProfile`，新增一套配方不需要动任何渲染代码，也**不需要任何付费判断代码**。

实现上的约束：付费包只允许影响 `saturation` / `vignette` / `blur` / 未来的色温这类**表现层**参数，绝不允许携带行为逻辑（比如"付费包漂移阈值更宽松"）。一旦氛围能改行为，它就变成了功能付费墙。

### 2. 支持者版

同一个二进制、同样的功能，加一个徽章和致谢名单里的名字。纯自愿。GitHub Sponsors / 爱发电。

### 3. 周边

锚形状的实物、贴纸、键帽。与软件完全解耦。

### 4. 企业支持

部署咨询、内部分发支持、注意力管理工作坊。卖的是人的时间，不是软件的权限。

## 明确不做

| 方向 | 为什么不做 |
|---|---|
| Focus Lock / 复盘 / tab 级判定 做成 Pro | 这些是产品灵魂。锁了之后免费版就没什么可推广的了 |
| 托管云同步订阅 | 哲学第三条要求同步必须走用户自己的基础设施（iCloud Drive / Tailscale） |
| 去广告 / 去水印 | Anchor 里压根没有这些东西，加进来只为了卖掉是自伤 |
| 按设备数收费 | 需要账号系统与激活服务器，直接违背 local-first |

## 团队版：应该是另一个产品

真正的 B2B 收入不在这个仓库里。哲学文档已经把路留好了：

> 如果将来要做，会以姊妹项目或单独 fork 的形式存在。

要做团队/管理侧的产品，就另起一个仓库、另一套许可、另一套品牌语气。**不要共用 Anchor 的语气**——「桅杆上的瞭望员，不是狱卒」和"给管理者看的看板"是两种互相拆台的叙事，混在一起两边都不成立。

## 如果将来要推翻以上

那就**先改 [`product-philosophy.md`](product-philosophy.md) 第三条，再改代码**。那份文档开头写着"此文档不是 marketing，是约束"——它的价值全部来自于它真的约束了决定。绕过它加一个付费墙，损失的不只是这一条立场，而是那份文档以后还算不算数。
